# Kaggle native train-only preprocessing status

The requested Kaggle notebook no longer embeds a compressed assignment state. It reads raw train/test images, writes the 37 participant-reviewed seed IDs openly, performs crop/exclusion policy, extracts pretrained non-VLM visual features, fits KMeans/SVM/kNN/graph propagation on eligible train, balances eight classes using a uniform prior, and writes processed folders/manifest before model training. No test labels or archive annotation file are read.

After the mismatch audit, a held-out seed check was added. If three-fold seed agreement is below 0.70, the notebook saves its preprocessing diagnostic and raises a clear error **before GPU model training**. This guard is compiled but has not yet been rerun end-to-end on Kaggle. It is a safety gate, not a repair of the 1,016 label differences.

Local CPU execution of the actual notebook preprocessing cells completed on all 2,400 raw files: 1,886 eligible train samples (1,879 full + 7 crops), 27 held train, 480 unlabeled test, 1,865 train source groups. All eight classes have 235–236 samples after balanced allocation. This proves execution and structural output, not semantic label quality or full Kaggle Run All.

After the automatic assignment was frozen, a read-only comparison against the previous active processed manifest found **870 matching and 1,016 different labels** among the same 1,886 eligible sample IDs. The old manifest was never used by the Kaggle notebook for assignment/model selection. DINOv3 few-shot seed CV probes reached only ~0.35–0.46 agreement across three folds on the 37 seeds. This indicates the seed-only reconstruction does not recover the historical target assignment. The newly generated pipeline must not be claimed equivalent to the previous high-scoring pipeline.

The previous snapshot-based GPU notebook was preserved at `kaggle_processed_hybrid_v3_before_native.ipynb` solely as an experiment archive. It retains an embedded assignment payload and does not meet the participant's latest request for notebook-generated assignments. The target notebook is the native train-only pipeline. The historical assignment's complete fitting chain is not present in the main notebook; it reads `data/preprocessing_inputs.npz`. Reproducing that exact assignment from raw images would require porting and validating the original upstream method chain rather than relabeling the seed-only output as equivalent.
